# PrairieLearn oracle

A real PrairieLearn (`prairielearn/prairielearn:latest`, dev mode) in Docker,
seeded with SCENARIO.md's PrairieLearn part. Fake data only.

| | |
|---|---|
| container | `fx-prairielearn` (Postgres + Redis are bundled inside it; nothing else) |
| URL | `http://127.0.0.1:3100` (bound to localhost only: dev login has no password) |
| course | `./course`, mounted read-only at `/course`: `CPSC 121` "Models of Computation", instance `2026W1` "2026 Winter Term 1", timezone `America/Vancouver` |
| users | `fstudent@example.invalid` "Fake Student" (enrolled, status joined); `fprof@example.invalid` "Fake Prof" (course Owner, instance Student Data Editor) |
| secrets | `secrets.env` (UIDs, names; random passwords PL never checks) and `secrets.pl-config.json` (PL config: `courseDirs: ["/course"]`, random `secretKey`). Both gitignored, generated by up.sh |

## Up / seed / login / down

```bash
oracles/prairielearn/up.sh                          # idempotent: recreate container from scratch, sync course, seed users
uv run python oracles/prairielearn_oracle.py        # live check (add --save-fixtures to refresh fixtures/)
docker rm -f fx-prairielearn                        # down (all state lives in the container)
```

`up.sh` runs `seed.py`, which:
1. triggers PL's own **Load from disk** (`GET /pl/loadFromDisk` as the dev admin) and waits for the job in `job_sequences`, failing on any sync error;
2. creates `fstudent` and `fprof` by logging each in once (PL creates users at first login);
3. writes the enrolment (`enrollments`, status `joined`) and staff permissions (`course_permissions`, `course_instance_permissions`) into PL's Postgres with `docker exec psql`. Idempotent (`not exists` guards).

Self-enrolment is **off** in `infoCourseInstance.json`, so fstudent can reach the course only because of the seeded enrolment.

### Acting as the student

PL has no password login. Production PL trusts SAML/Shibboleth/Google/Azure/LTI.
In dev mode, `/pl/login` has a **dev_login** form that asserts a UID/name/UIN,
which is the local stand-in for an SSO assertion. `login.py`:

1. sets cookie `pl2_disable_auto_authn=true`. Without it, dev mode silently logs every cookie-less request in as the dev **admin** (`dev@example.com`), which is not what we want;
2. `GET /pl/login` (sets the session cookie), then `POST /pl/login` with `__action=dev_login, uid, name, uin, email, __csrf_token=` (empty works: no session yet);
3. checks "Fake Student" appears on `/pl`.

The adapter never sees any of this. At a real school the session comes from the browser after SSO.

## What the adapter reads (student-reachable only)

PL has no student JSON API (`/pl/api/v1` needs a staff token). So:

| GET | gives |
|---|---|
| `/pl` | the home page embeds `<script type="application/json" data-component="HomeCards">` with `studentCourses[]` (course `short_name`, `title`, instance `short_name`, `long_name`, `display_timezone`). Fallback: the "Courses with student access" link text `CPSC 121: Models of Computation, 2026 Winter Term 1` |
| `/pl/course_instance/<ci>/assessments` | one `<tr>` per assessment, grouped by set heading (`Quizzes`, `Homework`, `Labs`): badge (`Q1`), title, link, "Available credit" summary, and an **Access details** popover (`data-bs-content`, HTML-escaped table) with every credit window: `100% | 2026-09-01 00:00:00 (PDT) | 2026-10-02 23:59:00 (PDT)` |
| `/pl/course_instance/<ci>/assessment_instance/<n>/` | only when the row already links there (the student started it): used for `links_out` |

Adapter output: course `label="CPSC 121, 2026W1"`, `title="CPSC 121: Models of Computation, 2026 Winter Term 1"`, `term_hint="2026 Winter Term 1"`, `source_id` = course instance id. Items: `source_id="<ci>:<badge>"` (e.g. `1:Q1`).

## Real-server behaviours an adapter must handle

- **No single due date.** Dates are credit windows. `due` = latest end among windows with credit >= 100; `opens` = earliest start among the windows the student is shown. Quiz 1 has a later 50 % window (until 2026-10-09); `due` is still 2026-10-02 23:59.
- **Dates are printed with a zone abbreviation**: `2026-10-02 23:59:00 (PDT)`. After 2026-11-01 PL prints `(PST)`. The adapter maps the printed abbreviation to its offset (table + `GMT±h:mm`), and accepts other abbreviations only if the instance's display zone prints the same one at that instant. The summary text (`100% until 23:59, Fri, Oct 2`) has no year or zone. Don't use it.
- **Popover only shows windows that matter to the student.** 0 %-credit / `active:false` windows are omitted.
- **Not-yet-open assessments are invisible by default.** Legacy `allowAccess` lists an assessment only if a rule currently grants access. We add a `credit:0, active:false` "preview" window before Lab 4 opens (a common instructor pattern), so it's listed, but **without a link**: the student never sees its id. The adapter uses the assessments page plus the row label as a fragment (`.../assessments#L4`) as `url`, and says so in `notes`. The fragment keeps the url item-specific, so a generic link to the list page from another platform is never fusion link evidence. Links in an unstarted Exam's start page are not read (the list can't tell Exam from Homework, whose GET is a write). The real deep link `/pl/course_instance/1/assessment/1/` returns **403** to the student, with "Assessment will become available on 2026-10-20 00:00:00 (PDT)". Once it opens, the next fetch carries the deep link. `source_id` (badge) stays the same.
- **GET on an unstarted Homework's `/assessment/<id>/` is a write**: it creates an assessment instance and 302s to `/assessment_instance/<n>`. The adapter never fetches those. Exam-type assessments (our quizzes) show a "Start assessment" page on GET and create nothing.
- **Once started, the row links `/assessment_instance/<n>/`, not `/assessment/<id>/`,** and no student page reveals the assessment id again. So a Moodle/Canvas link to `/pl/course_instance/1/assessment/3/` (quiz1) matches the PL `url` exactly **only while the student hasn't started it**. After that, fusion must fall back to title evidence. The oracle deliberately never starts the quizzes. It does start Problem Set 3 (its url check is a student click), and afterwards its url is `/pl/course_instance/1/assessment_instance/1/`.
- **Multi-instance assessments** list a header row (`Q1`) plus rows `Q1#2`… The adapter keeps the header row only.
- **Assessment ids come from sync order** (alphabetical by directory on a fresh DB: lab4=1, ps3=2, quiz1=3, quiz2=4; instance 1). Stable across `up.sh`, but treat them as server facts: the oracle reads them from Postgres.
- Deep links for other platforms' seeds (`<PL:quiz1>`): `http://127.0.0.1:3100/pl/course_instance/1/assessment/3/`.
- The dev-mode navbar shows "Load from disk" even to students, and pages embed CSRF tokens. The oracle scrubs tokens from fixtures.
- `done` is left `None`. The list shows only a score ("Not started", "0%"), which isn't "submitted".
